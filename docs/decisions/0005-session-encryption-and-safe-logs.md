# Decision 0005: Encrypted Session Storage and Allow-listed Error Logs

## 상태

Accepted

## 날짜

2026-11-07

## 배경

`docs/security/security-principles.md`의 기준과 실제 코드를 대조하다가 두 곳의 차이를 확인했습니다.

- **세션 저장:** 기준은 "토큰은 보안 저장소 사용을 검토한다"였지만, 리프레시 토큰이 들어 있는 Supabase 세션이 AsyncStorage에 평문으로 저장되었습니다. `expo-secure-store`는 플러그인만 있고 코드에서 쓰지 않았습니다.
- **오류 로그:** 기준은 "로그에 위치, 메모, 사진 URI를 남기지 않는다"였지만, 프록시가 장소 이름과 주소, 네이버 응답 원문을 서버 로그에 남겼습니다. 앱은 오류 객체를 통째로 기록해 파일 경로나 DB 값이 섞일 수 있었습니다.

## 결정

### 세션

- SecureStore(iOS 키체인, Android Keystore)에는 256비트 키만 저장한다.
- 세션은 `expo-crypto`의 AES-GCM으로 암호화해 AsyncStorage에 저장한다 (`enc:v1:` 접두사).
- 이전 빌드가 남긴 평문 세션은 처음 읽을 때 암호화해 다시 저장한다. 업데이트로 로그아웃되지 않는다.
- 키와 맞지 않는 세션은 지우고 다시 로그인하게 한다.
- 웹은 SecureStore가 없어 기존 방식을 유지한다.

### 로그

- 앱은 오류에서 `name`, `code`, `status`만 남긴다 (`app/src/utils/error-log.ts`).
- 프록시는 장소 이름, 주소, 검색어, 네이버 응답 원문을 남기지 않고 상태 코드와 오류 코드만 남긴다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
| --- | --- |
| 세션을 SecureStore에 직접 저장 | 플랫폼이 큰 값을 거부할 수 있음. Expo SDK 56 문서에 일부 iOS가 약 2048바이트를 넘는 값을 거부했다고 나옴 |
| `aes-js` CTR 방식 (오래된 Supabase 블로그 예제) | 위변조를 감지하지 못함. SDK 56의 `expo-crypto`가 네이티브 AES-GCM을 제공함 |
| 평문 세션을 버리고 다시 로그인 | 업데이트만으로 모든 사용자가 로그아웃됨 |
| 로그에서 민감 필드만 지우기 | 새 필드가 생기면 다시 새어 나감. 남길 항목만 정하는 허용 목록이 기본적으로 안전함 |

## 영향

- `expo-crypto`는 새 네이티브 모듈이라 앱 재빌드가 필요하다. JS만 업데이트하는 배포로는 적용되지 않는다.
- `expo-crypto`가 문자열을 base64로만 받으므로 UTF-8 변환 함수를 직접 둔다 (`app/src/utils/utf8.ts`).
- 로그의 정보가 줄어 원인 파악이 다소 어려워진다. 오류 종류는 코드와 상태로 구분한다.
- 검증: WebCrypto의 실제 AES-GCM으로 돌린 jest 테스트, 재빌드한 iOS 시뮬레이터 체크리스트(기존 세션 유지, 재시작 후 유지, 재로그인 후 유지)
